# P2 多资产组合实现与验收

版本：v0.6.0  
范围：严格市场快照、组合估值、多资产模拟成交、组合风控、同步回测与离线五标的实验。

## 1. 实施目标

P2 解决原单标的架构中的核心估值缺陷：

```python
prices.get(symbol, 0.0)
```

该写法会把缺失价格的其他持仓按零估值，进一步污染净值、权重、回撤、风险预算和再平衡数量。v0.6.0 不再允许这种降级。

## 2. 严格 MarketSnapshot

新增 `MarketSnapshot`：

- 价格必须为有限正数；
- 标的名称统一大写；
- 明确区分 `open`、`close` 和 `mark`；
- 组合估值前检查每个非零持仓是否都有价格；
- 缺少任一价格立即抛出异常，不允许按零处理。

`Portfolio.market_value()`、`equity()`、`weight()`、`weights()` 和 `gross_exposure()` 均已接入这一约束。

## 3. 同步市场数据层

新增 `AlignedMarketData`，只保留所有标的共同拥有的时间戳，并生成：

- 同步收盘快照；
- 下一公共交易日同步开盘快照；
- 每个标的在决策时刻可见的历史切片；
- 非公共时间戳丢弃数量。

若同一公共交易日各标的开盘时间不一致，系统会拒绝运行，避免用不同时间的价格拼接一个虚假组合快照。

## 4. 多资产模拟成交

`PaperBroker` 新增 `rebalance_many()`：

1. 要求目标权重覆盖全部已有持仓；
2. 要求执行快照覆盖全部已有持仓和目标标的；
3. 先执行减仓和清仓；
4. 再执行加仓；
5. 每笔成交重新计算组合权益和可买数量；
6. 禁止负现金；
7. 保留手续费、滑点和整数股约束。

单标的 `rebalance()` 接口保持兼容，但当组合已有其他持仓时，调用方必须显式传入完整估值价格。

## 5. 组合级风险治理

新增 `PortfolioRiskGovernor`，默认参数：

```text
单标的最大权重：20%
组合最大总暴露：90%
最大持仓数量：5
组合最大回撤：15%
最低加仓置信度：45%
```

约束顺序：

1. 拒绝负权重；
2. 应用单标的权重上限；
3. 低置信度时阻止新增暴露，但允许减仓；
4. 超过最大持仓数量时保留目标权重最高的标的；
5. 超过总暴露时按比例缩放；
6. 触发回撤后对全部持仓强制清零；
7. 完成清仓后进入粘性 `HALTED`。

所有保护性减仓都绕过普通再平衡阈值和冷却期。

## 6. MultiAssetBacktestEngine

多资产事件循环在每个公共交易日执行：

```text
公共收盘时间
  → 为每个标的构建 EvidencePack
  → Quant / Context / Fusion / Critic / Regime
  → 生成各标的初始目标权重
  → PortfolioRiskGovernor 统一约束
  → 下一公共交易日开盘同步成交
  → 记录开盘后组合暴露
  → 下一收盘统一估值
```

结果包含：

- 每标的决策记录；
- 组合风险状态；
- 提议、风控和实际执行目标权重；
- 成交列表；
- 开盘后执行权重与总暴露；
- 收盘后持仓、权重、现金和净值；
- 数据对齐统计；
- 完整绩效指标。

## 7. 离线五标的数据与入口

新增确定性数据生成器：

```bash
make multi-sample
```

生成：

```text
data/multi_sample/
├── SPY.csv
├── QQQ.csv
├── AAPL.csv
├── MSFT.csv
├── NVDA.csv
├── *_news.jsonl
└── manifest.json
```

覆盖：

```text
2018-01-02 至 2025-12-31
2087 个工作日
```

这些数据是合成的软件测试夹具，不是真实历史行情，不得用于宣称投资收益。

完整离线运行：

```bash
make multi-backtest
```

输出：

```text
artifacts/multi_backtest.json
```

## 8. 验收结果

固定种子与默认配置下：

```text
同步交易日：2087
标的：AAPL、MSFT、NVDA、QQQ、SPY
成交数量：317
成交后最大总暴露：约 89.83%
成交后最大单标的权重：约 20.00%
负现金记录：0
风险状态：ACTIVE、LIQUIDATING、HALTED 均实际覆盖
```

组合最终收益为负只反映当前合成数据、交易成本和规则参数的结果，不构成策略有效性证明。P2 的验收重点是估值、约束、时间顺序和状态机正确性。

## 9. 自动化测试

新增测试覆盖：

- 缺失持仓价格必须失败；
- 非法价格必须失败；
- 多资产再平衡先卖后买；
- 单标的接口在存在其他持仓时要求完整快照；
- 单标的权重、持仓数量和总暴露约束；
- 全组合回撤强制清仓；
- 同步下一开盘执行；
- 成交后组合暴露不超过配置上限；
- 模拟账户不出现负现金。

P0、P1、P2 合计：

```text
45 项测试通过
Ruff 检查通过
compileall 通过
```

## 10. P3 边界

P2 仍是一次性回测系统。以下能力属于 P3：

- 持久化模拟账户；
- 订单和审批状态机；
- 待审批订单队列；
- 每日任务调度；
- 交易日历；
- 服务重启恢复；
- 通知与人工确认；
- 决策幂等和重复运行保护。

P3 仍应保持只做模拟盘，禁止真实资金交易。
