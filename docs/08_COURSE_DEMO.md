# 课程答辩演示流程

建议总时长：8–10 分钟。

## 1. 第 1 分钟：问题与取舍

说明参考项目的优点和不适合课程复现的部分：

- 多智能体角色丰富，但调用成本和依赖复杂；
- 数据源多，部分需要 API Key；
- 多轮语言辩论难以量化每个角色的贡献；
- 风险讨论不应替代确定性风控。

引出本项目目标：保留多智能体协作思想，改造成离线、可复现、可审计的模拟交易系统。

## 2. 第 2–3 分钟：系统架构

展示 README 中的流水线图，依次讲解：

1. CSV/JSONL 点时数据；
2. EvidencePack；
3. Quant 与 Context 两类互补分析；
4. Critic 证据审查；
5. Regime Guard 市场状态约束；
6. Risk Governor 硬风控；
7. Paper Broker 和下一开盘成交；
8. 报告、审计和 SQLite。

重点强调：LLM 风格模块不能直接控制订单，最终仓位必须经过确定性约束。

## 3. 第 4 分钟：原创改进点

建议突出三点：

### EvidencePack 与自动审计

每个结论必须引用证据 ID，并在运行后自动检查未来数据和虚假引用。

### Regime Guard Agent

不同于重复讨论的角色，该智能体输出明确的风险暴露倍率，并通过独立消融验证贡献。

### Run Bundle

每次实验保存数据哈希、Git 版本、配置、环境、审计和 HTML 报告，保证结果可追踪。

## 6. 第 8–9 分钟：实验结论

不要只说“收益率高”。建议表述：

- 在上涨样本中，买入持有收益更高；
- 完整智能体通过限制仓位显著降低回撤；
- 熊市场景中完整智能体约损失 0.70%，买入持有约损失 40.71%；
- Regime Guard 将四场景最差回撤从约 4.29% 降至约 2.60%；
- 风控消融带来更高收益和更多成交，同时提高回撤，说明约束真实生效；
- 当前结论体现风险收益权衡，而非证明真实盈利能力。

## 8. 常见提问回答

### 为什么还叫多智能体，而不是普通量化策略？

因为系统包含职责、输入和输出契约不同的独立决策模块，并通过结构化意见、证据引用、融合和消融验证协作效果；它不是把所有逻辑写在一个策略函数中。

### 为什么不完全照搬参考项目？

课程项目更重视可运行、可解释和可验证。十余个 LLM 角色会增加成本，却难以证明每个角色必要，因此采用少而有效的角色设计。

### 为什么完整智能体收益低于买入持有？

样例包含长期上涨阶段，低仓位策略必然牺牲部分收益。完整智能体主要优化回撤和跨环境稳定性，压力测试显示其在熊市和高波动阶段更稳健。

### MockLLM 算不算真正的大模型？

它是离线结构化推理替身，目的是保证课程验收可复现。接口已与具体实现解耦，后续可替换真实模型，而数据、风控、成交和审计链路无需修改。

### 如何证明没有未来数据？

数据结构显式保存 `available_at`，Provider 只返回决策时点之前的数据；测试和自动审计同时检查，并强制下一开盘成交。
